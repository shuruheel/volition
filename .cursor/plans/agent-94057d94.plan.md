# Agent Dashboard — Backend v1 Implementation Plan

### Scope and decisions

- **Auth**: Keep mock auth (future: Neon Auth/Auth0).
- **Voice**: Twilio outbound calls only, with pre-call approval + post-call summaries to the feed.
- **Integrations now**: Supermemory (graph memory), Browser-Use Cloud (browser tasks).
- **Defer to v2**: Composio Gmail + Google Calendar.
- **Stack**: Next.js 16 (App Router, Route Handlers), Vercel AI SDK 6 (Agent/Tools), Neon Postgres, TypeScript.

### Data model (Neon Postgres)

- `users` (for future, minimal now): id, email, name, created_at.
- `agents`: id, name, prompt, status, tools (string[]), created_at, updated_at.
- `activities`: id, agent_id, type, status, priority, created_at, payload (jsonb) — unified types only; exclude high-frequency noise by policy.
- `memories`: id, agent_id, provider_id (supermemory id), kind, created_at, metadata (jsonb).
- `calls`: id, agent_id, to_number, status, twilio_sid, started_at, ended_at, summary (text/jsonb).
- `tool_configs`: id, user_id, tool (enum: openai, neon, supermemory, browser_use, twilio), data_encrypted (text), created_at, updated_at.

### Backend APIs (Route Handlers)

- Agents
- `GET /api/agents` | `POST /api/agents`
- `PATCH /api/agents/:id` (status/prompt/tools)
- Activities
- `GET /api/activities?agentId=...&types=...`
- `POST /api/activities/:id/approve` | `/reject` | `/modify`
- Metrics
- `GET /api/metrics/key?agentId=...` → totals for: Total Spend, Active Tasks, Pending Approvals, Memories Added, Actions Done, Emails Sent, Calls Made
- Memories (Supermemory)
- `POST /api/memories/store` (explicit writes via tool), `GET /api/memories/search`
- Browser tasks (Browser-Use Cloud)
- `POST /api/browser/task` (create + optional polling), `GET /api/browser/task/:id`
- Calls (Twilio outbound only)
- `POST /api/calls` (initiate after approval) → creates Twilio call
- `POST /api/twilio/voice` (TwiML for outbound leg; returns <Connect><Stream .../ws></Stream></Connect>)
- `POST /api/twilio/status` (status callbacks)
- `WS /api/twilio/stream` (WebSocket proxy Twilio <-> OpenAI Realtime)
- `POST /api/calls/:id/summary` (server-side summarize, store activity)
- Tool configuration
- `GET /api/settings/tools` (masked), `POST /api/settings/tools` (create/update), `POST /api/settings/test` (connectivity test per tool)

### Agent orchestration (Vercel AI SDK 6)

- Create `lib/ai/agent.ts` with `ToolLoopAgent` using:
- `supermemoryTools(SUPERMEMORY_API_KEY)` for memory operations
- `browserTaskTool` (custom AI SDK tool) → calls `/api/browser/task`
- `logActivityTool` → writes `activities`
- Use `stopWhen` safeguards, input schemas via Zod, and `onStepFinish` to persist steps/usage.

### Twilio outbound voice flow

- Pre-call: user reviews a `phone_call` activity in dashboard and clicks Approve → `POST /api/calls` with agent_id, to_number, call context/instructions.
- Server creates Twilio call via REST; Twilio requests `POST /api/twilio/voice` → return TwiML `<Connect><Stream url="wss://.../api/twilio/stream?callId=..."/></Connect>`.
- WS proxy bridges Twilio Media Streams <-> OpenAI Realtime (g711 μ-law), config voice, VAD, and optional function calling for tool usage if needed.
- On call end (status callback), server triggers summary: fetch transcript segments from Realtime events buffer, summarize with `generateText`, persist to `calls.summary`, and append a `activities` row of type `phone_call` with summary.

### Supermemory integration

- Use `@supermemory/tools` with AI SDK for explicit memory control and a simple `storeMemory` endpoint.
- Persist reference rows in `memories` to count “Memories Added”.

### Browser-Use Cloud integration

- REST via `browser-use-sdk`: create task, stream optional progress, poll result; expose as AI SDK tool.
- Add domain allowlist and secrets mapping (from tool configs) in server routes.
