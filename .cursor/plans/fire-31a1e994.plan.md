# Session‑Based Firecrawl Research Plan

## Goals

- One research activity per agent run (session), aggregating across many searches.
- Use Firecrawl Search with `scrapeOptions` (top 3 links each query) and store full markdown to Supermemory.
- Properly formatted Markdown summaries in UI.
- Agent continues iteratively within tool‑call limit; on limit reached, finalize session and plan next run.
- Check Supermemory for prior knowledge before each session.

## 1) Firecrawl: unify Search+Scrape

- Update `lib/integrations/firecrawl.ts`:
  - Add `searchAndScrape({ query, limit=3, scrapeOptions: { formats: ['markdown','links'] }, sources?, categories? })`.
  - Return normalized: `{ items: Array<{ url, title?, description?, markdown?, links?: string[], metadata?: any }> }`.

## 2) Supermemory storage helper

- Add `lib/integrations/supermemory.ts`:
  - `storeMarkdown({ agentId, url, title, markdown }) -> { providerId }` (calls Supermemory with `SUPERMEMORY_API_KEY`).
  - Then POST to `app/api/memories/store` to persist reference: `{ agent_id, provider_id, kind: 'document', metadata: { url, title } }`.

## 3) Research Session API

- Add new handlers:
  - `app/api/research/sessions/start/route.ts` → create `activities` row: `{ type:'research', status:'in_progress', payload: { title, queries: [], links: [], notes: [], source:'firecrawl' } }` and return `{ session_id }` (use the new row id).
  - `app/api/research/sessions/[id]/append/route.ts` → merge into payload: append `queries[]`, `links[]`, `notes[]` (markdown chunks), and optional counters.
  - `app/api/research/sessions/[id]/complete/route.ts` → accept `{ summary? }`; if not provided, summarize `notes[]` via `generateSummary(...)`; set status `completed` and set `payload.summary`.

## 4) Unified AI tools

- New tool `lib/ai/tools/firecrawl-research.ts`:
  - input: `{ query: string, limit?: number, sources?: ('web'|'news'|'images')[], categories?: ('github'|'research'|'pdf')[], session_id?: string }`.
  - calls Firecrawl `searchAndScrape(...)` with `limit=3`.
  - For each returned item with `markdown`, call `storeMarkdown(...)`; collect `{url, title, providerId}`.
  - POST to `/api/research/sessions/[session_id]/append` with `{ query, links, notes: [per‑page short summary in markdown] }`.
  - returns compact `{ leads, savedCount }`.
- New tools:
  - `startResearchSession` → POST `/api/research/sessions/start` and return `session_id`.
  - `completeResearchSession` → POST `/api/research/sessions/:id/complete` with optional extra `summary`.
- Remove per‑search activity logging from old `firecrawl-search.ts` and `firecrawl-scrape.ts` (keep files but stop registering them).

## 5) Agent orchestration changes

- `lib/ai/agent.ts`:
  - Register: `startResearchSession`, `firecrawlResearch`, `completeResearchSession` when `agent.tools` includes `'firecrawl'`.
  - Before run: query Supermemory for recent related docs using the user prompt; append to `researchContext` (reuse `getRecentResearchContext` or add a `supermemorySearch(topic)` helper).
  - Track `currentSessionId` inside the run. On each `onStepFinish`, detect tool results:
    - if `startResearchSession` returned id → set `currentSessionId`.
  - On completion: if `currentSessionId` exists and run ended (finishReason or `currentStep === maxSteps`), call `/api/research/sessions/:id/complete` to finalize summary and mark activity `completed`.
  - Keep `planNextStep` tool but update guidance to prefer `firecrawlResearch` and to call `startResearchSession` once at beginning and `completeResearchSession` at end.

## 6) UI formatting

- Update `components/unified-activity-card.tsx` to render `payload.summary` (fallback `description`) with Markdown:
  - Add `react-markdown` and wrap with `className="prose prose-invert max-w-none"`.
  - Display `payload.links` (dedup, up to 10) under a Links section.

## 7) Prompt updates

- `docs/prompts/research-agent.md` and `lib/ai/prompts.ts`:
  - Instruct explicit sequence: `startResearchSession` → loop: `firecrawlResearch` (top 3) → `planNextStep` → … → `completeResearchSession`.
  - Stop conditions: no new high‑quality leads, unclear objectives, or needs user input.

## 8) Validation & limits

- Keep existing per‑route rate limiting.
- In `firecrawl-research` tool, hard‑cap per call `limit=3`; truncate any single markdown to 20–40k chars before upload if needed.

## 9) Tests/manual checks

- Verify a run generates exactly one `research` activity with aggregated summary, links, and notes.
- Verify Supermemory counter increases and each scraped page stored.
- Verify Markdown formatting renders correctly in activity feed.
